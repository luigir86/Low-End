# How Low End is built

A guide for developers. For what the app does, see the [README](../README.md) and the [user guide](user-guide.md).

## In one paragraph

Low End is a single-module Flutter app for Android (package `com.luigir86.low_end`). It has three sections (metronome, harmony, tuner) that share one audio engine, one microphone and one set of settings. There is no backend, no database and no network code. State lives in plain `ChangeNotifier` controllers, passed down the widget tree by one `InheritedWidget`; there is no state-management package.

## Layers

```
screens (features/*/…_screen.dart, …_panel.dart)   what you see and touch
        │ listen to
controllers (…_controller.dart, app/settings.dart)  state and rules, no Flutter widgets
        │ call, through small interfaces
outputs (audio/*_output.dart, mic_input.dart, …)   sound, microphone, notification, wakelock
        │ backed by
packages: flutter_soloud, record, audio_service, wakelock_plus, shared_preferences
```

Every outside thing sits behind an interface with a silent or fake twin (`ToneOutput`/`SilentToneOutput`, `ClickOutput`/`SilentClickOutput`, `MicInput`/`FakeMicInput`, `BackgroundAudio`, `ScreenAwake`/`FakeScreenAwake`). The tests use the twins, so they need neither a phone nor a sound card.

## Sound

- **One engine.** `soloud_engine.dart` starts the [SoLoud](https://solhsa.com/soloud/) engine once, on the first sound, and lets that sound wait 300 ms while the phone's output ramps up (a click right at the start came out as a double "tra-ta"). The Xiph codecs are left out of the build (`pubspec.yaml`, `no_xiph_libs`), since all sounds are made in memory.
- **Whole bars as loops.** The metronome does not fire timers. `ClickSound` renders **one bar** of clicks (a short synthesised woodblock tick, higher on the first beat; softer clicks for the subdivisions (`Subdivision.inner`: where each falls in the beat, the swung ones at 60% of the pair, as MuseScore's Swing); with the click on 2 and 4, beats 1 and 3 left silent, with what is inside them) as a PCM buffer and `BarLoopPlayer` loops it gaplessly, so the time cannot drift. Changing the tempo or time signature renders a new bar.
- **Harmony.** `PianoSound` renders the chord (or the bars of a progression) from 14 recorded notes pitched up and down, into a loop **of the same length** as the metronome's bar. `LoopTransport` makes a second loop that starts while another plays wait for the next bar line, so chords and clicks stay together.
- **Sustained tone.** `DroneSound` makes the steady, warm tone of a held note as a seamless loop; its pitch never wavers, so it is a true reference.
- **Volume** is the phone's media volume. Each section starts and stops its own sound from the middle of its dial; the tuner pauses the others.

## Tuner

`RecordMicInput` streams 16-bit PCM from the `record` package, `Pcm16Decoder` turns it into samples, and `PitchDetector` finds the fundamental with the **YIN** algorithm (28–2800 Hz, 28–700 Hz for the bass, where it rejects voices and hiss; a short period is placed by its multiples further along the curve, so high notes are as precise as low ones). `TunerController` smooths the readings, owns the listening/paused state and starts the microphone only after the first frame is drawn (`test/startup_test.dart`). The tuner pauses the metronome and the harmony while it is on screen, so the microphone hears only the instrument.

## Playing with the screen off

`MediaNotificationAudio` (on `audio_service`) runs a foreground service of type `mediaPlayback` with a notification, so Android does not freeze the app. It asks for `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `POST_NOTIFICATIONS` and `WAKE_LOCK`. `WakelockScreenAwake` keeps the screen on, optionally, while something plays or the tuner listens.

## Settings

`AppSettings` keeps language, note names, reference A (every hertz from 415 to 445), screen-on, circle layout and the "guide seen" flag in `shared_preferences`, on the phone only (Android backup is off in the manifest). Unreadable settings never stop the app: it starts with the defaults.

## Look

All colours are in `lib/app/theme.dart` (bronze on ebony, always dark: one accent for the whole app), the font sizes and control shapes in `lib/app/style.dart`; `docs/style.md` is the style sheet that says what each is for, and `test/style_test.dart` keeps font sizes from being written anywhere else. The font is **Edwin** (regular and bold), with **Noto Music** supplying the ♩ that Edwin lacks; both are bundled and licensed under the SIL OFL. The launch screen colour in `android/app/src/main/res/values/colors.xml` must match the theme (`test/theme_test.dart` checks it). Note names follow the language (Do Re Mi with Italian octaves, La3 = 440, or C D E, A4 = 440) or the user's choice.

## Tests

`flutter test` runs everything (about 390 tests, around a minute): unit tests of the controllers, sound and pitch maths; widget tests of the screens; `accessibility_test.dart` (labels, touch targets, contrast); `startup_test.dart` (nothing heavy at launch); and `test/review/` (the layout matrix: English and Italian, the phone set to light or dark (the app stays dark), text scale up to 2×, phones down to 320×568 and landscape (915×412, 640×360, a tablet), with no overflow and the tab dots showing while something plays). The tests load Roboto and the Material icons from `test/fonts/`.

`test_screenshots/ui_review_test.dart` renders every screen to PNG for visual review and for the Play Store screenshots:

```
flutter test test_screenshots/ui_review_test.dart --update-goldens
```

CI (`.github/workflows/ci.yml`) runs `dart format --set-exit-if-changed lib test`, `flutter analyze` and `flutter test` on every push to `main` and every pull request.

## Release

See [store/README.md](../store/README.md): `flutter build appbundle --release` for Google Play, signed with the upload key in `android/key.properties` (git-ignored). Raise the number after `+` in `pubspec.yaml` before each upload. To install on a phone, `flutter build apk --release` and `adb install -r build/app/outputs/flutter-apk/app-release.apk` keep the app's data when the signing key is the same.

## No network

There is no networking code in `lib/`, the release manifest has no `INTERNET` permission and no font or file is downloaded. How this was checked is in [offline.md](offline.md).
